# TaoCode UI：编辑感与视觉张力

用于 TaoCode 的 Vue 面板、设置页、弹层和对话界面。目标是让界面有清楚的主次、节奏和辨识度，同时保留可追溯的功能与文案。这里的视觉方向是本项目的设计选择，不代表 ZCode 或 IntelliJ IDEA 的上游规范。

## 视觉方向

- 以编辑器画布、面板和真正可交互的控件构成层级。沿用仓库现有的暖纸色、石墨色和克制的陶土色强调；颜色从 src/tokens.css 的语义变量取。
- 用对齐变化、疏密、字号层级、明确分隔线和留白建立张力。每个区域选定一个主焦点，辅助状态收低对比度。
- 几何要干净、利落。可交互控件才需要控件表面；不要让每一行都变成圆角卡片。
- 避免通用 AI 页面套路：渐变或外发光、玻璃模糊、到处使用胶囊与阴影、无数据支撑的统计卡、装饰性星光图标、为填空而增加的空状态标题或说明。
- 不要用装饰补偿信息层级。若一个区域显得空，先检查内容顺序、比例和锚点；不要新造标签、口号或状态。

## 先确认功能和文案

1. 改组件前，阅读 src/tokens.css、src/uiIcons.ts 和同类组件；涉及上游移植时，再核对 .tools/ZCode 或 IDEA 上游源码及本仓的移植判据。
2. 先追踪数据从设置/存储进入组件，再追踪动作如何到达宿主或服务。只有真实可执行、可持久化的能力才能表现为可用控件。
3. 文案只用上游、本仓真实状态或已经存在的动作名称。不要添加“尚未完成”“当前能力”等实现解释来填充界面；也不要删掉表达真实错误、权限、成功或来源行为所必需的文本。
4. 上游没有的交互逻辑不要补猜测实现。没有真实执行路径的能力先记为缺口，不画成正常开关或选择器。
5. 保持改动范围小。纯视觉重构优先改样式和结构，不改请求、权限、持久化或默认值。

## TaoCode 项目硬约束

- 颜色只用语义 token（如 --panel、--editor、--elevated、--text、--secondary、--muted、--accent、--line）；组件不要直接引用 --m-*，不要写裸 hex 或 rgb()。
- 间距、圆角、控件高度、动效优先从 src/tokens.css 已有的 --space-*、--radius-*、--ctrl-height-*、--dur-* 和 --ease 取。新增度量必须有名字和本地理由；有上游几何依据时注明出处，不凭感觉伪称上游值。
- 图标尺寸从 src/uiIcons.ts 的 iconSize.* 角色取。使用项目图标组件；纯图标按钮同时提供 title 和 aria-label。
- 中文正文遵循仓库字号下限；除纯英文/数字次级信息外，不用过小字号表达层级。
- 任何可压缩的 flex/grid 子项显式处理 min-width: 0；内容滚动区处理 min-height: 0。长文本需换行、截断或在局部滚动，不能撑宽整个面板。

## 面板与弹层

- 面板按“固定头部 / 唯一主滚动区 / 固定操作区”组织；根容器和滚动容器均允许收缩。工具栏在窄宽度下换行或压缩，项目面板最窄按 180px 检查。
- 锚定弹层复用 src/components/AnchoredMenu.vue 等现有实现：使用共享开关状态，考虑宿主裁剪与视口边界，并保留 Escape、焦点和键盘导航语义。不要为同屏控件各自造一套浮层行为。
- 需要的颜色和几何优先补入共享 token；不要在单个 Vue 文件中私造第二套主题。

## 交付前检查

- 窄面板、长文件名/长文本、空状态、消息较多、菜单打开和键盘操作都没有溢出、裁剪或失焦。
- 亮/暗主题只通过语义 token 表现；检查焦点环、禁用态和选中态仍可辨认。
- 对照上游与本地服务确认每个显示出来的动作都能执行，状态文本与真实状态一致。
- 只有实际打开目标宿主并查看目标界面后，才能声称视觉验收完成；浏览器欢迎页不能代替 Agent 面板验收。
