  定位手段值得复用：挪开 `AppData\Local\TaoCode\projects.json` 后不崩 → 缩小到"打开项目"路径；
  `python -c subprocess.run('./TaoCode.exe', timeout=..)` 取退出码（TimeoutExpired=存活，RC=崩溃码）。

## ★ 事故与修复：删掉持久化键导致应用启动即退出（用户实际报错的那条）

**用户看到的**：`The saved configuration is invalid; the original file was kept.`

**根因（两个叠在一起）**：
1. **读盘复用了 UI 补丁的严格校验**：`native/projects.cpp` 的 `validate_document()` 里直接调 `validate_general_patch(value.at("general"))` / `validate_editor_patch(value.at("settings"))`，而这两个函数用 `known_keys(...)` **遇未知键即 fail**。我在 B1-c 系列里删掉了 4 个键（`syncOnFocus` / `deleteToTrash` / `restoreLastProject` / `autoSave`），但**磁盘上的状态文件里还有它们** → 校验失败 → `STATE_CORRUPT` → 应用启动即退出。冒烟从 ALIVE 变"提前退出"就是这么来的。
2. **修的时候又踩了一个 UB**：`prune_unknown()` 里用 `object.erase(it)` 边遍历边删 —— **`nlohmann::json::erase(iterator)` 只对数组有效**，对 object 属未定义行为 → `projects_lifecycle` **SEGFAULT**（被 ctest 抓到）。

**修法**：
1. 读盘与收补丁分开：新增 `prune_unknown(Json&, keys)`，在 `validate_document` 里**先剪掉当前版本不认识的键**再走严格校验。语义对齐 IDEA：`XmlSerializer` 对未知标签是**忽略**，`noStateLoaded()` 再补默认值 —— 旧版本写过、新版本删掉的键**不能让文件变成"损坏"**。
2. 键表收敛为**唯一一份**：新增 `editor_setting_keys()` / `general_setting_keys()`，UI 补丁校验与读盘剪枝共用，避免两处漂移。核对结果：编辑器 **38/38**、general **14/14**，双向零差集。
3. `prune_unknown` 改成"先收集未知键，再按键 `erase(key)`"。
4. **回归测试**（`native/projects_test.cpp`）：构造一份带 4 个已删键 + `general.legacyKeyFromAnOlderBuild` 的状态文件，断言：能加载、旧键被剪掉、其余取默认值、**读取不重写用户的文件**；同时保留原有"类型非法仍判 STATE_CORRUPT"的断言（剪枝只针对未知键，不放过坏值）。

**验证**：原生构建 RC 0 零告警 · `ctest` 全绿（含新增断言）· **冒烟恢复 ALIVE**。

**教训（写进长期记忆）**：
- **动持久化字段（删/改名）时，必须同时改"读盘路径"的容忍度**；`known_keys` 这种校验默认只该用于「外部输入」，不该用于「自己的旧存档」。
- **`nlohmann::json` 对 object 的 `erase(iterator)` 是 UB**；object 只能按键删。数组才能用迭代器。
- 这次是"冒烟测试"抓出来的 —— 而它恰好属于用户刚说的"该跑冒烟"的类型（改动了启动时会读的状态校验）。

### B1-g 续 3 · 修复嵌套 UI 自己的**样式**错误（用户点名"嵌套UI风格错误"）

给菜单加了子菜单之后，样式层有 4 个缺口，这批全部修掉：

1. **子菜单父行完全没有 hover/选中样式**（最严重）：渲染结构是 `.dropdown > .menu-submenu-anchor > button.menu-submenu-trigger`，而样式选择器是 `.dropdown > .menu-item`（直接子代）—— 中间隔了 anchor，**一条都匹配不上**。结果：父行既没有 hover 高亮，子菜单打开时也不保持选中（IDEA 的父行在子菜单打开时是选中态）。修法：给 `.menu-submenu-trigger` 补上与 `.dropdown > .menu-item` 相同的盒样式 + `:hover` / `:focus-visible` / `[aria-expanded='true']` 三态。
2. **子菜单没有入场动画**：父级 `.dropdown` 是 `motion.div`（opacity 0→1、y -4→0、scale .985→1、0.16s cubic-bezier(.16,1,.3,1)），子菜单是裸 `div` → 突然弹出。修法：CSS `@keyframes menu-submenu-in` 用同一组参数，并加 `@media (prefers-reduced-motion: reduce) { animation: none }`（项目里父级也有 reducedMotion 分支，两边要一致）。
3. **长子菜单溢出视口**：`openSubmenu` 原来直接 `top = box.top - 4`，「布局」这种多行子菜单会顶出屏幕底部。修法：计算 `below`（父行下方的剩余空间），不足 180px 且上方更宽裕就**向上翻转**（用 `bottom:` 锚定，让浮层贴着父行下缘往上长）；两个朝向都把 `maxHeight` 夹进视口，长列表靠自身滚动。定位与高度收敛成一个 `submenuStyle` 对象绑到 `:style`。
4. **above 朝向的 transform-origin**：`menu-submenu-above` 用 `bottom left`，动画从下缘长出来，与父级一致。

设置树那侧复核过：`.settings-child` / `.settings-grandchild` / `.settings-group` + caret 都有样式，无需改。

**本批未跑冒烟**（桃的新规则：没动启动路径就不跑）—— 本批只动 CSS 与菜单交互逻辑，不涉及原生与启动。

### B6 · 前端拆分：file 菜单迁出（47 行 → src/menus/fileMenu.ts）

`FileMenuContext` 30 个成员（refs + 回调），`createFileMenuRows(ctx)` 返回 47 行菜单（含两级嵌套的

**关键教训（务必记住）**：菜单是**内联在 `const menus = [...]` 数组字面量里**的——把组文本直接替换成
`const xxx = {...}` 语句 = **往数组里插语句** → TS1005/TS1128 一片。正确做法：
① const 块放 `menus` 定义**之前**；② 数组内原位置只放 `{ menu: 'file' as const, label: '文件', rows: fileMenuRows },`。
（我为此浪费了好几轮编译循环——之前 tools 菜单能过是因为它在数组**外**的独立变量。）

**类型手法（提速用）**：
- 给 App 侧 ctx 对象**加接口标注**（`const ctx: XxxContext = {...}`）→ tsc 立刻报出**具体哪个成员**不兼容；
  不加标注只有笼统的"对象不可赋"，靠猜要好几轮。
- 回调成员参数统一用 `any`（参数逆变：接口写 `unknown`/窄字面量会让 App 的窄函数赋不进去）。
- ComputedRef/WritableComputedRef 的 value 与手写 `{ value: T }` 在同构时兼容；`Pane` 这类内部联合
  先用 `any` 并在注释里标明"类型随后续批次收紧"。

**1) 欢迎页 UI 错位重叠（截图确诊）**：`WelcomePage.vue` 里 `menu-backdrop`（最近项目行菜单的遮罩）
