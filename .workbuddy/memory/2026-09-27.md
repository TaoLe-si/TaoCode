## 批（架构）：main.cpp 107 处 `else if` → 哈希 `switch` + 路由三清单机检

### 桃的指令
「把 main.cpp 的 if else 改为 switch」。

### 落地
- `native/main.cpp:41-56` 新增 **constexpr FNV-1a + `operator""_h`**：`std::string` 不能直接
  `switch`，编译期把 `case "app.state"_h` 折成 `std::uint64_t`。**哈希碰撞不是静默风险** ——
  两个名字撞一个值就是重复 `case`，MSVC 直接 C2196。
- `native/main.cpp:1044` 起：`if (auto it = routes.find(method); …) result = it->second(params);`
  `else switch (fnv1a(method)) { … }`，**120 个 case 标签 + 1 个 `default: throw UNKNOWN_METHOD`**；
  原先的 `routes` 小表（3 个方法名）保留在最前面。
- 跨行语句（`file.readBinary` / `file.usages`）收进 `case x: { … break; }` 块，续行缩进 = 语句行 +4。
- 嵌套的 `if/else if (method == …)` 分组（dap 步进组、dap.stackTrace 组、history 组、plugin 组、
  search 组…）**保持 if/else**，它们是 case 体内的二次分派，不是外层链的一部分。

### 顺带修好的两个真 bug（都是「只在运行时暴露的空功能」）
1. **`main.cpp` 的参数白名单漏键** → `newPath` / `command` / `arguments` / `previousResultId`
   全被丢掉：`willRenameFiles`、`executeCommand`、pull 诊断发出去的是空参数。
   现在改为**整体转发**（只摘掉 kind/path/line/character），各分支只读自己认识的键。
2. **kind 清单漏 4 项** → `completionItemResolve` / `diagnostic` / `prepareRename` / `foldingRange`
   掉进 `lsp->request`（不认识它们）回 `LSP_BAD_KIND`，而前端各自的 `catch {}` 把错误吃了：
   折叠区间、pull 诊断、重命名预校验、补全 resolve **四个已宣布完成的功能在界面上全哑**。
   测试之所以全绿：`lsp_semantics_test`/`lsp_coding_test` 直接调 `Session::semantic`，**绕过 main.cpp**。
   结构性修法：`Session::request`（hover/completion/definition）与 `Session::semantic`（其余）
   **互为兜底**（不认识的 kind 转交对方，`semantic` 的兜底仍是 `LSP_BAD_KIND` 且不再转交 → 不递归）；

### 新增回归测试
`tests/routing-parity.test.mjs`（4 条，机检三张清单）：前端 `Method` union ↔ 原生 case+`routes`、

**这个测试直接就是上面第 2 个 bug 的守门人。**

### 过程教训（血的）
- 第一版转换脚本有三处错：① 「独立 `}`」判定没校验缩进 → 把所有**嵌套**收尾大括号也当成 case 收尾；
  ② 单语句分支没做括号配平 → `break;` 被插到跨行语句中间；③ 生成的 switch 头把 `routes` 那一行覆盖掉。
  → 正确做法：**只处理缩进恰为 12 的行** + `(`/`[` 配平决定语句边界 + 每次写入前用
  「名称多重集相等 / 无缺失收尾 / 无不可达 break」三条自检，不自检通过就不写盘。
- 逆向还原（switch → if/else）时同样踩了「正则多吃 `case `」和「按行缩进推深度」两个坑。
  可靠的深度来源是**独立扫描括号（先剥字符串与注释）**，不是行缩进。
- 有 `build/main.cpp.ok` 这类可编译备份，才敢连续试错 —— 每次大改前先留一份能编译的副本。
