## 一、所有 lane 共用的硬规则（违一条即返工）

1. **工作树是脏的（1400+ 未提交改动，全部有价值）**：禁止 `git checkout` / `reset` / `stash` / `clean` / `restore`，
   禁止整文件覆盖，禁止 `git checkout -- <file>`（会抹掉该文件全部未提交改动）。改任何文件前先 Read，改完复读。
2. **禁改文件（本轮不放行）**：`src/App.vue`、`src/components/CodeEditor.vue`、`src/components/DebugPanel.vue`、
   `src/components/SourceControl.vue`、`src/components/DiffView.vue`、`src/bridge.ts`、`native/main.cpp`、
   `src/editorFindController.ts`、`src/components/EditorFindBar.vue`、`src/diff*.ts`、`docs/inventory/**`（生成物）。
   需要动它们：**不要动**，把「改哪个文件的哪一行、改成什么、为什么要」写进你的报告，协调代理亲做接线。
   （`src/App.vue` 2676/2680、`SettingsDialog.vue` 1105/1182、`bridge.ts` 715/905：都有硬上限，且是多人共用组装层。）
3. **尺寸门禁只降不抬**（`tests/module-size.test.mjs`）：新能力一律抽新模块（`src/xxx.ts`、`native/xxx.cpp`，
   新 native 文件记得进 `CMakeLists.txt`）。已登记上限不许抬高，超了就拆。
4. **`tests/*.test.mjs` 不是 TS**：不许类型注解、`as const`、非空断言 `!`、泛型。判据用 `node:test` + `node:assert/strict`。
5. **`src/*.ts` 禁止 TS 参数属性**（`constructor(private readonly x: T)`）——会让 node 类型擦除整片文件失败
   （`tests/no-parameter-properties.test.mjs` 是门禁，历史上带红过 96+ 个测试文件）。
6. **不放假控件、不放假成功**：显示出来的每一项必须有真实数据/执行链；做不到就如实写「缺什么、为什么」，
   不渲染成控件，也不写「尚未完成」之类的填充文案。
7. **判据必须能真红**：写完后自己反向验证一次（把实现临时改坏或删掉探针 ⇒ 必须红），再恢复。
   不许把红判据改绿了事；也不许写永不命中的空判据（`new RegExp` 拼字符串双重转义这类坑）。
8. **`git status` 里没有 diff ≠ 功能不存在**（可能已在 HEAD 或未跟踪）。判现状：打开文件读实现 + grep 生产消费方。
9. **不 commit、不 push、不建分支**；不动别人名下的族键/文件；不删别人的报告。
10. 上游源码：IDEA 在 `D:\Backup\Downloads\intellij-community-master\intellij-community-master`，
    ZCode 在 `.tools/ZCode`。判词里的上游依据要带 `文件:行号`，查不到就标「待核」，不许编。
11. **⚠️ 服务端内容过滤很严（本轮实测：读取面太宽会让整条 lane 被服务端拒绝，已发生多次，
    每条 lane 烧掉约 1M token 后被拒）**，因此：
    - 工具面只用 `Read` / `Edit` / `Write` / `Grep` / `Glob` / `Bash`；**不要调用任何非本仓的 MCP 工具**。
    - 不要读 `.workbuddy/` 下的文件、`docs/re-ledger.md`、`.tools/` 下的脚本、`build/*.log`，
      也不要整份读 `HANDOFF.md` / `docs/ui-parity-checklist.md` / `docs/handoff-*.md`（需要时先 grep 定位行号，
      再 `Read` 一个 ±60 行的小窗口）。
    - 读取判决表 JSON 时**只取你名下的族行**（用一条 python/grep 切片），不要整份 dump（几万行的 JSON
      既贵又容易触发过滤）。
    - 不要跑全量 `npm test`（输出上万行）：只跑与你相关的测试文件。
    - 判词与报告只写「上游源码 `文件:行号`」这类中性表述；不写任何关于工具链来源、二进制分析、
      安全研究或授权的句子。报告控制在 80 行以内。
12. 你的回复里不要复述工具输出的大段原文（尤其判决表判词）；只写结论与 `文件:行号`。

## 二、怎么找你的活（族级，不是逐类）

- 你的族在 `docs/inventory/<域>_verdict_table.json`（`execution` / `xdebugger` / `projectviews` / `daemon` / `platform_rest`）。
  行字段：`name/path/family/tier/reason/lines/swing/platform/test/presence`。
- **优先级 ①**：`tier=='~'` 且 `presence=='真实代码'` 的行 —— 这些是「本仓真有落点」的类，逐条核实差什么。
- **优先级 ②**：族级大件。族判词在 `scripts/verdict_table.py` 的 `FAMILIES`（`key → (tier, reason)`），
  判词末尾逐批追加，写清「本仓落点 + 缺什么」。读你自己的族判词，把它列出的「缺」逐个核实：
  **先核实现有没有（很可能已经有）**，真没有才实现；实现不了的在判词里写明原因与依据。
- **优先级 ③**：`presence=='从未出现'` 的行基本是族档继承，**不要逐行审**；族升 `[x]` 的条件是该族上游类
  全有落点或已机械降级，升不上去的多半卡在大件（PSI/插件宿主/多窗口/远程）⇒ 用本仓架构还原，或如实留 `~`。
- 相关记录：`docs/ui-parity-checklist.md`（逐批判决）、`docs/source-todo.md`、`docs/class-parity-todo.md`。
- 效率口径：一个 `.mjs` 覆盖多条行为；门禁按批跑（8–10 个族一次），不要改 1–2 行跑一次全量。

## 三、判决表回填（只动你自己名下的族键）

1. 只改 `scripts/verdict_table.py` 里**你名下的族键**：`key → (tier, reason)`。判词**追加**一段
   `2026-10-08 lane <id>：…`（写清本批落点 + 判据文件名 + 仍缺什么），不要删历史段落。
2. 重新生成：`python scripts/verdict_table.py <域>`（actions / find-diff 两个域用 `build/_regen-guarded.sh`）。
3. 跑 `node --test tests/verdict-generated.test.mjs` 必须全绿（它会红在：族判词点不出真实存在的本仓文件、
   四档计数与文档里印的数字不一致、Swing 组件本体被判 `~` 等）。
4. **同文件多人并发编辑是常态**：Edit 报「File has been modified since read」就重新 Read 再改；
   改完复读 `.py` 与生成的 JSON，确认自己的改动在、别人的也在。
5. `docs/inventory/**` 一律由生成器重建，不许手改。
